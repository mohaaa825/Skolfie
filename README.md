# skolfie

skolfie estimates whether a piece of text was written by a person or
generated by an AI model. It combines stylometric features, a from-scratch
**Burrows' Delta** implementation and a scikit-learn ensemble, and includes
a Gradio app for analysing text, collecting feedback and retraining.

## Status

**This is a prototype that is being rebuilt.** Be aware of the following:

- **No trained model ships with the repo.** You have to train one yourself
  (see below). `models/*.joblib` is git-ignored.
- **Accuracy has not been measured.** No held-out evaluation on real data
  has been done yet, so treat any score the app prints as uncalibrated.
- **The seed texts are a test fixture, not a dataset.** The 25 human and
  25 AI texts in `tests/fixtures/seed_texts.py` are synthetic and
  deliberately clear-cut. They are useful for smoke tests (`--seed-demo`)
  and unit tests. A model trained on them is not a usable detector.

### Roadmap

1. **Real data corpus.** The pipeline is in place (see "Build the data
   corpus" below); the full corpus is built locally and is not committed.
2. **Held-out evaluation.** Report accuracy, F1 and AUROC on data the model
   never saw, split by source and generator (`scripts/train.py --test-size`
   is the starting point).
3. **DistilBERT + features model.** Replace the current blend with a
   fine-tuned DistilBERT classifier combined with the stylometric features.

## Install

Requires Python 3.10 or newer.

```bash
python -m venv .venv && source .venv/bin/activate
pip install -e ".[app,dev]"     # app = Gradio UI, dev = pytest + ruff
```

The core install (`pip install -e .`) covers training and the library
without the UI.

### NLTK data

`skolfie.features.stylometric` uses NLTK's sentence and word tokenizers and
its POS tagger. Importing the module never downloads anything. Fetch the
data once after installing:

```bash
python -c "from skolfie.features.stylometric import download_nltk_data; download_nltk_data()"
```

This downloads `punkt`, `punkt_tab`, `averaged_perceptron_tagger` and
`averaged_perceptron_tagger_eng`. Without them, the module falls back to
regex tokenization and suffix-based POS heuristics. The feature names stay
the same, but some values (POS ratios, sentence splits) change. Use the
same mode for training and for prediction.

## Build the data corpus

One command downloads the public datasets, normalises them into one schema
(`skolfie/data/schema.py`), cleans, length-filters and deduplicates them,
and writes `data/processed/corpus.parquet` plus `manifest.json` (counts,
content hash, corpus version) and `stats.md`.

```bash
pip install -e ".[data]"
python scripts/build_corpus.py                       # all sources
python scripts/build_corpus.py --sources hc3,autextification --no-download
```

| Source | What it is | How it is fetched |
|---|---|---|
| `hc3` | HC3 English: ChatGPT vs human answers (ELI5, open QA, CS wiki, finance, medicine) | Hugging Face `Hello-SimpleAI/HC3` |
| `autextification` | AuTexTification 2023 subtask 1 (EN): tweets, reviews, wiki, news, legal | Hugging Face `symanto/autextification2023` |
| `m4gt` | M4GT-Bench English: ChatGPT, GPT-4, davinci, Cohere, Dolly, BLOOMz | Google Drive only: put `SubtaskA.jsonl` in `data/raw/m4gt/` (e.g. `gdown --folder https://drive.google.com/drive/folders/1xC-n5hHiXmaCLmA0q3p8Cbyd7Dk0dpDE`) |
| `fresh` | Text from current models, generated by you | `scripts/generate_ai_texts.py` |

**No local disk or a blocked network?** Open
[`notebooks/build_corpus.ipynb`](notebooks/build_corpus.ipynb) in Google
Colab and use Run all. It builds the corpus straight into
`My Drive/skolfie/data/processed/`.

Files can also be placed by hand under `data/raw/<source>/`; each loader's
`MANUAL_DOWNLOAD` string says exactly which files. A source that fails is
reported and skipped (use `--strict` to fail the build instead).

### Generate fresh AI text

The public datasets only contain older generators. To add current models,
set an API key and run:

```bash
pip install -e ".[generate]"
python scripts/generate_ai_texts.py --provider anthropic --n 500 --dry-run   # plan + cost estimate
ANTHROPIC_API_KEY=... python scripts/generate_ai_texts.py --provider anthropic --n 500
```

Providers: `anthropic`, `openai`, `gemini`, and any OpenAI-compatible server
(`together`, `groq`, `ollama`, `vllm`, `openai-compatible`). Runs are
resumable and append to `data/raw/fresh/<model>.jsonl`. Rebuild the corpus
afterwards to include them.

## Evaluate

Fixed, versioned splits test generalisation rather than memorisation:
`train` / `val` / `test`, plus `test_ood_generator` (GPT-4 and Cohere, never
trained on), `test_ood_domain` (news, never trained on) and `test_short`
(under 100 words). All answers to one HC3 question stay on the same side.
See `configs/splits.json`.

```bash
python scripts/make_splits.py --corpus data/processed/corpus.parquet --out-dir data/processed
python scripts/evaluate.py --corpus data/processed/corpus.parquet \
    --splits data/processed/splits.parquet --model tfidf --out-dir reports/tfidf
python scripts/evaluate.py --compare reports/*/report.json
```

Each run writes `report.md` (a report card: AUROC, F1, false-positive rate on
human text at 95% AI recall, calibration error, per split, with breakdowns by
generator, domain and source) and `report.json`. Models: `length` and
`tfidf` baselines, `ensemble` (the current prototype), or `joblib:PATH` for any
object with `predict_proba(texts)`. In Colab, use
[`notebooks/evaluate.ipynb`](notebooks/evaluate.ipynb), which reads the corpus
from and writes reports to Google Drive.


```bash
# Smoke test on the synthetic fixture texts (checks the pipeline, NOT a real model)
python scripts/train.py --seed-demo --out /tmp/demo_model.joblib

# Real training: CSV or Parquet with columns `text` and `label` (human / ai),
# e.g. the corpus built above
python scripts/train.py --data data/processed/corpus.parquet --test-size 0.2

# Also include reviewed rows from the app's feedback file
python scripts/train.py --data data/labeled.csv --feedback feedback_data.csv
```

By default the model is written to `models/detector_model.joblib`. Run
`python scripts/train.py --help` for all options.

## How it works today

> The pipeline below is the **current prototype behaviour**. The fixed
> 35/65 Burrows/ML blend in particular is slated for replacement (see the
> roadmap).

1. **Stylometric features** (`skolfie/features/stylometric.py`).
   `FeatureExtractor.extract_features(text)` returns a flat
   `{name: float}` dict of about 130 features in these groups:
   - *Basic counts and ratios*: word, sentence and character counts, plus
     average word and sentence length.
   - *Sentence structure*: standard deviation of sentence length,
     burstiness (std/mean), and maximum and minimum sentence length.
   - *Vocabulary richness*: type-token ratio, hapax legomena ratio and
     Yule's K.
   - *Punctuation*: overall punctuation density, plus a per-word rate for
     `, . ! ? ; : - "`.
   - *Readability*: average syllables per word and Flesch reading ease.
   - *Part of speech*: noun, verb, adjective, adverb and pronoun ratios.
   - *Function words*: the relative frequency of each of about 100 common
     English function words (`fw_*`). Burrows' Delta uses the same words.
   - *Repetition*: stopword ratio and repeated-bigram ratio.

   `features_to_vector(features, order)` turns the dict into a numpy vector
   with a fixed order and fills missing keys with 0.0.

2. **Burrows' Delta** (`skolfie/features/burrows_delta.py`). The model
   z-scores function-word frequencies across the training corpus and builds
   a "human" profile and an "AI" profile. A new text is scored by the mean
   absolute z-score distance to each profile.

3. **ML ensemble** (`skolfie/models/ensemble.py`). This is a soft-voting
   ensemble of a Random Forest, a Logistic Regression and a small MLP. Its
   input is the scaled stylometric features, the Burrows' Delta distances
   and character n-gram TF-IDF features.

4. **Final score (prototype)**:
   `ai_probability = 0.35 × Delta probability + 0.65 × ensemble probability`
   (`BURROWS_WEIGHT` in `ensemble.py`). The weight is a hand-picked constant
   and has not been tuned or validated.

5. **Explanation**. The app shows the Delta and ML breakdown, the function
   words that most set the text apart, and the "top contributing features".
   That last list is a heuristic: Random Forest importance multiplied by how
   unusual the text's value is. It is not SHAP and does not show cause.

## Feedback loop

In the app you can mark a prediction as AI-generated or human-written. The
correction is added as a row to `feedback_data.csv` with the text, the
prediction, your label, a timestamp and the extracted features. Pass that
file to `scripts/train.py --feedback` to retrain on it.

## Limitations

- About 130 features plus TF-IDF on small datasets is a high-dimensional,
  low-sample setup that overfits easily. Training-set accuracy means
  nothing here. Use `--test-size` or, better, a separate held-out corpus.
- Stylometric signals depend on genre, topic and generator. A model trained
  on one domain may not carry over to another.
- AI-text detection is probabilistic. Don't base high-stakes decisions on
  this tool alone, such as academic misconduct cases. A human must review
  the result.

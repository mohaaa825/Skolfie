# skolfie

skolfie estimates whether a piece of text was written by a person or
generated by an AI model. It combines stylometric features, a from-scratch
**Burrows' Delta** implementation and a scikit-learn ensemble, and includes
a Gradio app for analysing text, collecting feedback and retraining.

## Status

**This is a prototype that is being rebuilt.** Be aware of the following:

- **No trained model ships with the repo.** You have to train one yourself
  (see below). `models/*.joblib` is git-ignored.
- **The app and CLI run the new models.** `python -m skolfie.app` and
  `skolfie check` load the stacked verdict model, the feature model (for the
  reasons) and the chunk-trained transformer (for Mixed and the highlights)
  through `skolfie.service.Detector`.
- **The seed texts are a test fixture, not a dataset.** The 25 human and
  25 AI texts in `tests/fixtures/seed_texts.py` are synthetic and
  deliberately clear-cut. They are useful for smoke tests (`--seed-demo`)
  and unit tests. A model trained on them is not a usable detector.

### Roadmap

Done: (1) repo cleanup, (2) a 259k-text corpus from HC3, M4GT and
AuTexTification, (3) held-out evaluation with length and TF-IDF baselines,
(4) the feature model (style + GPT-2 + Delta features into LightGBM),
(5) DistilBERT + features, (6) a calibrated combiner with Human /
Uncertain / AI verdicts, (7) Mixed human/AI detection by chunks, (8)
explanations, (9) evasion tests, (10) fairness checks, (11) the web app
and CLI. Next: (12) retraining from feedback. A REST API is left for when
there is a system to integrate with; `Detector.check()` already returns
JSON-ready results.

The target use is student essays and other longer English texts.

### NLTK data

`skolfie.features.stylometric` uses NLTK's sentence and word tokenizers and
its POS tagger. Importing the module never downloads anything. Fetch the
data once after installing:

```bash
python -c "from skolfie.features.stylometric import download_nltk_data; download_nltk_data()"
```

This downloads `punkt`, `punkt_tab`, `averaged_perceptron_tagger` and
`averaged_perceptron_tagger_eng`. Without them, the module falls back to
regex tokenization and suffix-based POS heuristics. The feature names stay
the same, but some values (POS ratios, sentence splits) change. Use the
same mode for training and for prediction.

## Build the data corpus

One command downloads the public datasets, normalises them into one schema
(`skolfie/data/schema.py`), cleans, length-filters and deduplicates them,
and writes `data/processed/corpus.parquet` plus `manifest.json` (counts,
content hash, corpus version) and `stats.md`.

```bash
pip install -e ".[data]"
python scripts/build_corpus.py                       # all sources
python scripts/build_corpus.py --sources hc3,autextification --no-download
```

| Source | What it is | How it is fetched |
|---|---|---|
| `hc3` | HC3 English: ChatGPT vs human answers (ELI5, open QA, CS wiki, finance, medicine) | Hugging Face `Hello-SimpleAI/HC3` |
| `autextification` | AuTexTification 2023 subtask 1 (EN): tweets, reviews, wiki, news, legal | Hugging Face `symanto/autextification2023` |
| `m4gt` | M4GT-Bench English: ChatGPT, GPT-4, davinci, Cohere, Dolly, BLOOMz | Google Drive only: put `SubtaskA.jsonl` in `data/raw/m4gt/` (e.g. `gdown --folder https://drive.google.com/drive/folders/1xC-n5hHiXmaCLmA0q3p8Cbyd7Dk0dpDE`) |
| `fresh` | Text from current models, generated by you | `scripts/generate_ai_texts.py` |

**No local disk or a blocked network?** Open
[`notebooks/build_corpus.ipynb`](notebooks/build_corpus.ipynb) in Google
Colab and use Run all. It builds the corpus straight into
`My Drive/skolfie/data/processed/`.

Files can also be placed by hand under `data/raw/<source>/`; each loader's
`MANUAL_DOWNLOAD` string says exactly which files. A source that fails is
reported and skipped (use `--strict` to fail the build instead).

## Evaluate

Fixed, versioned splits test generalisation rather than memorisation:
`train` / `val` / `test`, plus `test_ood_generator` (GPT-4 and Cohere, never
trained on), `test_ood_domain` (news, never trained on) and `test_short`
(under 100 words). All answers to one HC3 question stay on the same side.
See `configs/splits.json`.

```bash
python scripts/make_splits.py --corpus data/processed/corpus.parquet --out-dir data/processed
python scripts/evaluate.py --corpus data/processed/corpus.parquet \
    --splits data/processed/splits.parquet --model tfidf --out-dir reports/tfidf
python scripts/evaluate.py --compare reports/*/report.json
```

Each run writes `report.md` (a report card: AUROC, F1, false-positive rate on
human text at 95% AI recall, calibration error, per split, with breakdowns by
generator, domain and source) and `report.json`. Models: `length` and
`tfidf` baselines, `ensemble` (the current prototype), or `joblib:PATH` for any
object with `predict_proba(texts)`. In Colab, use
[`notebooks/evaluate.ipynb`](notebooks/evaluate.ipynb), which reads the corpus
from and writes reports to Google Drive.

### Feature model (roadmap step 4)

`--model features` trains LightGBM on three feature groups:

- `sty_*`: about 40 stylometric features (`skolfie/features/style.py`), all
  rates or ratios so they don't track text length; no NLTK needed.
- `lm_*`: GPT-2 perplexity, burstiness (spread of surprise across tokens and
  sentences) and token-rank statistics (`skolfie/features/lm.py`). Needs
  `pip install -e ".[features]"` and, for a full corpus, a GPU.
- `delta_*`: Cosine and Burrows' Delta distances to the human and AI
  word-frequency profiles (`skolfie/features/delta_features.py`). The
  training rows get out-of-fold values, so their own labels never leak in.

```bash
python scripts/evaluate.py --corpus data/processed/corpus.parquet \
    --splits data/processed/splits.parquet --model features \
    --cache-dir data/cache --save-model models/features.joblib --save-predictions
```

`features-nolm` skips GPT-2 (CPU only); `features-rf` and
`features-nolm-rf` use a random forest instead of LightGBM. `--cache-dir`
stores the style and GPT-2 features by text hash, so a re-run only refits
the classifier. The report card adds a feature-importance table. In Colab
use [`notebooks/feature_baseline.ipynb`](notebooks/feature_baseline.ipynb)
on a T4 GPU runtime.

### Transformer + features model (roadmap step 5)

`--model transformer` fine-tunes DistilBERT (`distilbert-base-cased`, so
case and punctuation are kept) together with the step 4 style and GPT-2
features: the [CLS] vector and a small network over the standardised
features are joined before the final layer (the Annepaka et al. design).
`transformer-text` drops the features, to measure what they add. Training
needs a GPU; use [`notebooks/transformer.ipynb`](notebooks/transformer.ipynb)
on a Colab T4. `--hf-model`, `--max-length`, `--epochs` and `--batch-size`
change the defaults.

### Calibrated combiner and verdicts (roadmap step 6)

`scripts/stack.py` combines models from the predictions they saved with
`--save-predictions`: a logistic regression over their logits, fitted on
`val` (which none of them trained on), gives one calibrated P(ai). It also
sets the verdict cut-offs on `val`: **AI** only where at most `--max-fpr`
(default 1%) of human texts score, **Human** only where at most
`--max-miss` (default 5%) of AI texts score, **Uncertain** in between. The
report card adds a verdict table per split.

```bash
python scripts/stack.py --corpus data/processed/corpus.parquet \
    --splits data/processed/splits.parquet \
    --member features=reports/features/predictions.parquet \
    --member transformer=reports/transformer/predictions.parquet \
    --model-path features=models/features.joblib \
    --model-path transformer=models/transformer.joblib \
    --save-model models/stacked.joblib --out-dir reports/stacked
```

The saved `StackedModel` loads the member models itself; `predict()`
returns the verdicts. In Colab use
[`notebooks/stack.ipynb`](notebooks/stack.ipynb) (CPU is enough).

### Mixed texts (roadmap step 7)

The corpus has no texts that are part human and part AI, so
`scripts/eval_mixed.py` makes them: it splices passages of a human and an
AI text from the same source and domain (patterns `ha`, `ah`, `hah`,
`aha`; same question for HC3), records where the AI parts are, and adds
pure human and AI texts. A set from `val` tunes the decision rules and a
set from `test` is reported on.

A saved model scores each whole text and each chunk of about 60 words
(whole sentences). Two rules are compared on the three-way task Human /
AI / Mixed:

- **chunk rule**: Mixed when enough chunks score clearly AI and enough
  score clearly human;
- **whole-text rule** (baseline): Mixed when the whole-text score falls in
  a middle band.

The report gives macro-F1 for both, Mixed recall per splice pattern, and
how well the AI chunks match the true AI spans (character-level F1 and the
boundary error in words).

```bash
python scripts/eval_mixed.py --corpus data/processed/corpus.parquet \
    --splits data/processed/splits.parquet \
    --model models/transformer.joblib --out-dir reports/mixed-transformer
```

In Colab use [`notebooks/mixed.ipynb`](notebooks/mixed.ipynb) (GPU).

Single chunks are harder to score than whole texts, so `--model
transformer-chunks` (in `evaluate.py`) trains the step 5 model on every
training text plus one random ~60-word chunk of it, with the same label.
[`notebooks/chunks.ipynb`](notebooks/chunks.ipynb) trains it, reruns the
Mixed evaluation and compares it with `transformer` (GPU). The rules are
tuned so that at most `--max-false-mixed` (default 5%) of pure human texts,
and of pure AI texts, are called Mixed.

### Explanations (roadmap step 8)

`skolfie.explain.Explainer` gives every verdict its five strongest reasons:
exact SHAP contributions of the feature model (LightGBM), each with its
direction and a plain-language reason ("low vocabulary variety, typical of
AI text"), plus the step 7 chunk scores as a heatmap. "Typical of AI text"
is only said when the value really is closer to the AI median on reference
texts; otherwise the reason says what the model did ("...; the model counts
this toward AI"). When the feature model alone points the other way from the
verdict, the explanation says so (`feature_model.agrees`), since its features
then do not explain the verdict. The output is plain JSON:
`{label, verdict, p_ai, chunks, highlights, top_features, feature_model}`.
`scripts/explain.py` writes a review sheet for 20 random test texts
(`review.md` to fill in by hand, `review.html` to read); in Colab use
[`notebooks/explain.ipynb`](notebooks/explain.ipynb).

### Evasion tests (roadmap step 9)

`scripts/make_attacks.py` builds attacked copies of test texts: typos,
synonyms, Cyrillic look-alike letters, zero-width spaces, T5 paraphrasing
(GPU), simulated human edits (a share of the sentences swapped for human
ones), and, with an API key, LLM paraphrasing, "humanizer" rewrites and
regeneration at low and high temperature. Noise attacks are also applied
to human texts, to check they don't cause false alarms.
`scripts/eval_robust.py` gives a robustness table per attack (AUROC, AI
recall at 0.5 and at the 1%-FPR cut-off, false alarms on attacked human
text) and compares models. For adversarial training,
`make_attacks.py --split train --share S` builds attacked training copies
and `evaluate.py --extra-train PATH` adds them to the training set
(attacked copies of evaluation texts are dropped). In Colab use
[`notebooks/robust.ipynb`](notebooks/robust.ipynb).

Against the Unicode tricks, every model first runs the text through
`skolfie.robust.normalize.normalize_for_scoring` (in training and at
scoring): invisible characters are deleted, fullwidth and other disguised
letters are folded, and Cyrillic or Greek look-alikes become Latin letters,
but only inside Latin words, so real Russian or Greek text is untouched.
What it undid is reported as the explanation's `obfuscation` counts and
shown as a warning in `review.html`, `review.md` and the app, since
ordinary text rarely contains either.

### Fairness check (roadmap step 10)

`scripts/eval_fairness.py` measures the false-positive rate (human text
flagged as AI, i.e. P(ai) above the model's AI threshold) per subgroup,
each with a 95% Wilson interval: corpus human texts of `test` and
`test_ood_domain` by domain, source, length (<50, 50-99, 100-199, 200-399,
400+ words) and technical text by length, plus external sets built by
`scripts/build_fairness_sets.py`: TOEFL essays by non-native writers and
essays by native writers from Liang et al. (2023, "GPT detectors are biased
against non-native English writers"; MIT), and ELLIPSE essays by English
learners by proficiency and grade (Crossley et al. 2023; CC BY 4.0). Human
essays that GPT-4 polished or simplified are reported apart, never as human
false positives, and the sets' AI texts as recall. The threshold is the
model's own `cutoffs["ai_threshold"]` (the stacked model), else the one
that flags 1% of the `val` human texts. A group is **far above average**
when its FPR is at least 2x the corpus-wide human FPR, at least 2 points
above it, and its interval's lower bound is above it; groups under 30
texts are too small to judge. Each far-above group becomes a sentence in
`known_limitations.json` for the app ("Essays by non-native English
writers are flagged as AI 12% of the time (vs 1% for human text in our
test data). Treat an AI verdict on such text with caution."). With a
feature model at hand, the report also gives each group's median GPT-2
perplexity, vocabulary variety and word / sentence length, since
predictable wording is what trips detectors on non-native writing. In
Colab use [`notebooks/fairness.ipynb`](notebooks/fairness.ipynb).

## How it works today

> The pipeline below is the **current prototype behaviour**. The fixed
> 35/65 Burrows/ML blend in particular is slated for replacement (see the
> roadmap).

1. **Stylometric features** (`skolfie/features/stylometric.py`).
   `FeatureExtractor.extract_features(text)` returns a flat
   `{name: float}` dict of about 130 features in these groups:
   - *Basic counts and ratios*: word, sentence and character counts, plus
     average word and sentence length.
   - *Sentence structure*: standard deviation of sentence length,
     burstiness (std/mean), and maximum and minimum sentence length.
   - *Vocabulary richness*: type-token ratio, hapax legomena ratio and
     Yule's K.
   - *Punctuation*: overall punctuation density, plus a per-word rate for
     `, . ! ? ; : - "`.
   - *Readability*: average syllables per word and Flesch reading ease.
   - *Part of speech*: noun, verb, adjective, adverb and pronoun ratios.
   - *Function words*: the relative frequency of each of about 100 common
     English function words (`fw_*`). Burrows' Delta uses the same words.
   - *Repetition*: stopword ratio and repeated-bigram ratio.

   `features_to_vector(features, order)` turns the dict into a numpy vector
   with a fixed order and fills missing keys with 0.0.

2. **Burrows' Delta** (`skolfie/features/burrows_delta.py`). The model
   z-scores function-word frequencies across the training corpus and builds
   a "human" profile and an "AI" profile. A new text is scored by the mean
   absolute z-score distance to each profile.

3. **ML ensemble** (`skolfie/models/ensemble.py`). This is a soft-voting
   ensemble of a Random Forest, a Logistic Regression and a small MLP. Its
   input is the scaled stylometric features, the Burrows' Delta distances
   and character n-gram TF-IDF features.

4. **Final score (prototype)**:
   `ai_probability = 0.35 × Delta probability + 0.65 × ensemble probability`
   (`BURROWS_WEIGHT` in `ensemble.py`). The weight is a hand-picked constant
   and has not been tuned or validated.

5. **Explanation**. The app shows the Delta and ML breakdown, the function
   words that most set the text apart, and the "top contributing features".
   That last list is a heuristic: Random Forest importance multiplied by how
   unusual the text's value is. It is not SHAP and does not show cause.

## Feedback loop

In the app you can mark a prediction as AI-generated or human-written. The
correction is added as a row to `feedback_data.csv` with the text, the
prediction, your label, a timestamp and the extracted features. Pass that
file to `scripts/train.py --feedback` to retrain on it.

## Limitations

- About 130 features plus TF-IDF on small datasets is a high-dimensional,
  low-sample setup that overfits easily. Training-set accuracy means
  nothing here. Use `--test-size` or, better, a separate held-out corpus.
- Stylometric signals depend on genre, topic and generator. A model trained
  on one domain may not carry over to another.
- AI-text detection is probabilistic. Don't base high-stakes decisions on
  this tool alone, such as academic misconduct cases. A human must review
  the result.
- Detectors flag some human writing more often than other, notably
  non-native English and short texts. `scripts/eval_fairness.py` measures
  this per group; see its `known_limitations.json` for the groups where the

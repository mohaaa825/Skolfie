# Skolfie

Skolfie checks whether a student essay (or another longer English text) was written by a
person or generated by an AI model. It gives a verdict, **Human / Uncertain / AI / Mixed**,
with the AI likelihood, the AI-looking passages highlighted and reasons a teacher can read.
Checking a text runs locally: no text is sent to an external AI service.

Results are probabilistic. Never use them as the only basis for a misconduct decision.

**No trained models ship with the repo.** They are trained in Google Colab by
[`notebooks/retrain_modern.ipynb`](notebooks/retrain_modern.ipynb) and written to Google
Drive (`My Drive/skolfie/models_v3/` and `reports_v3/`). Point the app or the CLI at those
folders, or at a portable folder made with `skolfie bundle`.

## Install

Python 3.10 or newer.

```bash
python -m venv .venv && source .venv/bin/activate
pip install -e ".[features,app]"   # torch, transformers, LightGBM, Gradio: needed to run models
pip install -e ".[dev]"            # pytest, ruff (and LightGBM) for development
```

Other extras: `data` (dataset downloads) and `generate` (API clients for generating AI essays).
The old stylometric model (`skolfie/features/stylometric.py`) uses NLTK data; fetch it once with
`python -c "from skolfie.features.stylometric import download_nltk_data; download_nltk_data()"`.

## Quick start

Check files from the command line:

```bash
skolfie check essay.docx --models-dir /path/to/models_v3 --reports-dir /path/to/reports_v3
skolfie check essays/ --models-dir models --format csv --out results.csv --html pages/
cat essay.txt | skolfie check - --bundle bundle/
skolfie bundle --models-dir models --reports-dir reports --out bundle/   # portable folder
skolfie info --bundle bundle/                                            # what was loaded
```

`check` reads .txt, .md, .docx and .pdf files and folders, and prints a table (or CSV / JSON
with `--format`); `--html DIR` writes one page per essay with highlights and reasons.

From Python, `skolfie.service.Detector` is the one entry point the app and the CLI use:

```python
from skolfie.service import Detector

detector = Detector.from_dirs("models_v3", "reports_v3")   # or Detector.from_bundle("bundle/")
result = detector.check(text)
result["label"], result["p_ai"], result["reasons"], result["warnings"]
```

Run the web app (Gradio):

```bash
python -m skolfie.app --models-dir /path/to/models_v3 --reports-dir /path/to/reports_v3
python -m skolfie.app --bundle bundle/
```

It serves on `http://127.0.0.1:7860`. `--share` or a non-local `--host` requires a login
(`--auth USER:PASSWORD`, or the `SKOLFIE_APP_AUTH` variable). `--show-feedback` adds a panel for
collecting teacher feedback. In Colab, [`notebooks/app.ipynb`](notebooks/app.ipynb) starts the
app with a password-protected share link, checks a Drive folder of essays, and can publish the
app as a Hugging Face Space (`skolfie space build` / `skolfie space publish`).

## How it works

1. **Data.** `scripts/build_corpus.py` builds one corpus (`skolfie/data/schema.py`) from public
   datasets (HC3, M4GT, AuTexTification), PERSUADE 2.0 student essays, long human academic texts
   (peS2o paper sections, CC BY / BY-SA student theses) and fresh essays by current Claude and
   Gemini models, shipped in [`data/ai_essays/`](data/ai_essays/). `scripts/make_splits.py`
   makes versioned, leak-checked splits; `configs/splits_modern.json` holds out
   `claude-haiku-5-5` to measure a model never trained on.
2. **Feature model** (`skolfie/models/feature_model.py`): LightGBM on style features
   (`skolfie/features/style.py`), language-model features (`skolfie/features/lm.py`: perplexity,
   burstiness, token ranks; GPT-2 by default, `Qwen/Qwen2.5-1.5B` in `retrain_modern.ipynb`),
   Binoculars features from a Qwen2.5-1.5B / Qwen2.5-1.5B-Instruct pair
   (`skolfie/features/binoculars.py`) and Burrows' / Cosine Delta distances
   (`skolfie/features/delta_features.py`).
3. **Transformer** (`skolfie/models/transformer_model.py`): a fine-tuned DeBERTa-v3-large
   (on a GPU with bf16 and at least 22 GB) or DistilBERT (e.g. a T4), joined with the style and
   LM features. `BACKBONE = "auto"` in the notebook picks it.
4. **Stacker** (`skolfie/models/stacker.py`): a calibrated logistic regression over the two
   models, with cut-offs set on validation data: **AI** only where at most 1% of human texts
   score, **Human** only where at most 5% of AI texts score, **Uncertain** in between.
5. **Mixed and highlights** (`skolfie/mixed/`): a chunk-trained transformer (else the main
   one) scores ~60-word chunks; a text is **Mixed** when chunks clearly disagree.
6. **Explanations** (`skolfie/explain/`): SHAP contributions of the feature model turned into
   plain-language reasons. Inputs are normalised against Unicode tricks
   (`skolfie/robust/normalize.py`), and known fairness limitations (e.g. English learners)
   are shown with AI and Mixed verdicts.

## Training pipeline

[`notebooks/retrain_modern.ipynb`](notebooks/retrain_modern.ipynb) runs the whole pipeline on
Google Drive in two runs, to keep GPU time down:

1. on a **CPU** runtime: corpus, splits, leak check (`scripts/check_leaks.py`) and style
   features, then it stops;
2. on a **GPU** runtime (L4 or A100 for DeBERTa): LM and Binoculars features, the feature
   model, the transformer, optionally the chunk transformer (`TRAIN_CHUNKS`) and
   leave-one-family-out evaluation (`RUN_LOFO`), the stacker and a summary.

Each step is a script under [`scripts/`](scripts/) (`build_corpus.py`, `make_splits.py`,
`evaluate.py`, `stack.py`, `eval_mixed.py`, `explain.py`, `eval_fairness.py`, ...); run one
with `--help` for its options. `evaluate.py` writes a report card (`report.md`, `report.json`)
per model; `--compare` puts several side by side.

Other notebooks: `generate_gemini_batch.ipynb` and `generate_modern.ipynb` generate AI essays
through APIs (CPU); `explain.ipynb` and `fairness.ipynb` produce the reasons' reference values
and the known limitations the app shows; `robust.ipynb` runs evasion attacks; the remaining
step notebooks (`build_corpus`, `evaluate`, `feature_baseline`, `transformer`, `stack`,
`chunks`, `mixed`) run single steps on the older `data/processed/` and `models/` folders.

## Limitations

- Detectors flag some human writing more often than other, notably texts by non-native English
  writers and short texts. `scripts/eval_fairness.py` measures this per group and writes the
  `known_limitations.json` the app shows.
- Accuracy depends on the generators and genres seen in training; essays from newer or unseen
  models can score lower.
- AI-text detection is probabilistic. A human must review every result.
